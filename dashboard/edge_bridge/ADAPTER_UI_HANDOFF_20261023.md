# 학습 어댑터 → 실시간 화면 연결

## 센서별 최근 100개 생성과 읽기

기존 화면 라디오 아래의 센서 선택(전체/301/302/305)과 **최근 100개 보고서 생성하기** 버튼을 사용한다. 선택한 센서의 수신 순서 기준 최근 최대 100개를 요청 시점에 고정하고, 그 안에서는 오래된 기록부터 1번으로 생성한다. 새 수신 로그가 추가돼도 목록은 변경되지 않는다. 100개를 모두 기다리지 않고 생성된 첫 보고서부터 읽을 수 있다. Prev/Next와 번호 선택으로 이동한다. 100개 미만이면 현재 수신된 전체 개수를 표시한다.

생성 요청은 `report_batches`, `report_batch_items`에 저장되고 기존 GPU worker가 먼저 처리한다. 단일 worker이므로 브로커 수신은 계속하면서 생성 요청을 순차 처리한다. worker 재시작 시 중단된 항목만 복구한다. 기존 개별 보고서는 덮어쓰지 않는다. **이전 생성 목록**에서 저장된 묶음을 다시 열 수 있다.

검증 미통과·생성 실패도 항목과 원문을 그대로 표시하며 **이 보고서를 유지하겠습니까?** 질문에 유지/유지하지 않음을 선택한다. 선택은 `report_retention_events`에 기록한다. 이 선택으로 자동 검사나 Judge 판정을 변경하거나 감사 원문을 삭제하지 않는다. 301/305의 별도 로그 형식은 현재 설명형 생성기에서 해석하지 못할 수 있으며, 이 경우에도 실패 사유와 원본을 확인하고 유지 여부를 결정할 수 있다.

테스트: 센서별 최근 100개 고정, 새 로그 수신 시 목록 유지, 순차 처리, 실패 항목 보존, 유지 선택 기록, 중단 복구, 첫 보고서 선택, Prev/Next 경계, 화면 재표시 검사 통과. 실제 DB에서 301/302/305 센서별 목록 표시를 확인했다.

## 설명형 보고서로 전환

사용자의 기존 보고서 문체 요청에 따라 기본 생성 형식을 `prose`로 변경했다. 학습된 어댑터는 유지하고, 브로커에서 받은 단일 로그를 관측값 → 해석의 한계 → 추가 확인의 세 문단으로 생성한다. 최신 대기 기록부터 생성하며 서로 다른 원본 기록에 보고서를 공유하지 않는다. 이전 보고서는 보존한다. 한 번의 추론 완료 시간에 따라 새 보고서 표시가 지연될 수 있다.

`edge_bridge/broker_prose.py`가 입력 로그로부터 관측 문장을 계산하고 Qwen이 이를 보존하여 해석·확인 문단을 작성한다. 관측 문장 일치, 해석의 임의 수치, 형식, 일부 확정 표현, 표준 용어 등을 검사한다. 자동 검사는 의미적 정확성에 대한 Judge나 작업자 승인을 대체하지 않는다. 검사 실패 출력도 원문과 실패 사유를 저장한다.

기존 필드 형식은 `--report-style rcaeval`로 선택할 수 있다. 기본은 `--report-style prose`이다. UI는 `models-streamlit.service`로 실행하며 코드 변경 후 해당 서비스를 재시작한다.

2026-10-23 Copilot CLI 작업을 이어서 연결을 정리했다.

- 모델: `Qwen/Qwen3-4B-Instruct-2507`, NF4 4비트, GPU 추론.
- 어댑터: `llm/finetuning/runs/qwen-korean-rcaeval/adapter`.
- `qwen-korean-rcaeval-v2`에는 manifest만 있고 완성된 어댑터가 없어 사용하지 않는다.
- 장비 연결: `3.39.173.120:7777`, TCP Protobuf SensorMsg/SensorsMsg 수신.
- 저장: `edge_bridge/data/tcp-reports.sqlite3`.
- 화면: 기존 Streamlit의 **센서 보고서 · 실시간**. 5초 자동 갱신과 최신 완성 보고서 따라보기를 사용한다.
- 기존 외부 터널: https://recipient-adelaide-reach-completely.trycloudflare.com

실행은 Copilot 임시 프로세스에서 사용자 systemd 서비스로 옮겼다. 비정상 종료 시 재시작한다. 사용자 서비스 파일은 `/home/ubuntu/.config/systemd/user/edge-bridge-remote.service`이다.

```bash
systemctl --user status edge-bridge-remote.service
systemctl --user restart edge-bridge-remote.service
tail -f edge_bridge/data/remote-adapter.log
```

화면에는 실행 중인 어댑터, 선택한 보고서의 실제 생성 모델, 보고서 연결 건수와 자동 검사 통과·미통과 건수가 표시된다. 생성 완료와 검사 통과는 별개다. 현재 실제 출력에서 `unbound numeric assertion` 등 검사 실패가 확인되어 **검증되지 않은 보고서**로 표시한다. Judge·작업자 검토 완료로 표시하지 않는다. 모델 품질 개선이나 추가 학습은 이 연결 작업에 포함하지 않았다.

보고서 재사용은 같은 생성 모델·어댑터, 같은 전체 계산 근거, 같은 카드 버전, 검사 통과일 때만 허용한다. 경보 단계가 같아도 측정값·시각이 다르면 새로 생성한다. 이전 보고서는 보존한다. 모델 추론 중에도 별도 heartbeat를 기록한다.

검증: Protobuf 입력·중복 방지, 어댑터/측정값 변경 시 새 보고서 생성, 한국어 필드·용어 검사, 화면 탐색 및 검사 실패 표시 테스트 통과. 실제 DB로 Streamlit AppTest에서 예외 없이 어댑터와 미검증 출력 표시를 확인했다. 로컬 화면과 외부 터널 HTTP 200을 확인했다.
